# 玩法试炼场 · roomlab-v9（单玩法沙盒）

双人「合作/互坑」解谜的**玩法沙盒**。目标：**把每个玩法独立试玩，验证「单个玩法好不好玩」**；确定哪些好玩，再按密室主题去嵌套组合。

> 🌐 **线上试玩链接**：https://loran-f.github.io/roomlab/ （GitHub Pages，两台设备打开同一链接，各选玩法 + 角色 + 语音协作）

## 为什么拆成单玩法

之前一局 = 迷宫→转盘→剪线 三关串联，测的是"流程节奏"，单玩法好坏被稀释。v7 拆成**玩法大厅**，每个玩法一局独立（各带倒计时 + 通关判定 + 再来一局），可以快速判断"哪个玩法值得留下、哪个砍掉"。

## 玩法大厅（十一个入口，可插拔）

**「信息不对称」协作（两台设备 · 一人操作一人指挥）：**

| 玩法 | 图标 | A 现场 | B 后方 | 单局 | 失败代价 |
|---|---|---|---|---|---|
| **迷宫走线** | 🗺️ | 盲走探针（视野十字 5 格），听指挥 | 全图：绿安全线 + 红陷阱点，逐句指挥 | 120s | 碰墙 −5s / 踩陷阱 −8s |
| **转盘对接** | 🎛️ | 报目标指令卡号给 B、转针、报针位、喊锁才按 | 指令卡对照表：查卡号得目标刻度，指挥左/右，喊锁 | 90s | 锁错 −3s |
| **剪线排雷** | 🧨 | 报 6 根颜色→剪→再报剩余→剪，共 3 步 | 三步剪线规则树：听报色给答案 | 90s | 剪错任意一步 = 爆炸 |
| **对暗号·接头** | 📖 | 看 4 个抽象符号（没名字只能描述），输 4 位密码 | 密码本：10 符号 ↔ 数字对照，听描述认图翻译 | 120s | 输错 −3s |
| **锅炉校准** | 🌡️ | 只看到压力表读数（漂移），按 ⬆⬇ 调、报数 | 握安全区间（40~60），指挥加/减/稳住 | 120s | 撞 0 / 100 = 爆炸 |
| **记忆暗格** | 🧠 | 看 6 位密码 5 秒，口述给 B，听 B 报回输入 | 密码记录器：A 报一位按一位，报回给 A | 120s | 输错 −3s |

**「双人同屏」实时合力（一台设备 · 各按半边屏）：**

| 玩法 | 图标 | 玩法 | 单局 | 失败代价 |
|---|---|---|---|---|
| **物资空投** | 🧺 | A 按住左半屏← / B 按住右半屏→，合力控同一个接货员 | 60s | 接坏物 −3s / 超时未接够失败 |
| **双人护盾** 🆕 | 🛡️ | A 守左半区 / B 守右半区，各自按住自己的半屏升起护盾片挡陨石 | 60s | 漏陨石全队耐久 −1，扣完失败 |
| **双人抬梁** 🆕 | 🏗️ | A 抬左端 / B 抬右端；砖落到梁上会向低的一侧滚，两人要倾斜梁把砖**滚进梁正中间的收集口**才算收下（梁平着不动砖就停住收不了） | 60s | 砖滚出两端 5 次失败 |
| **双人节拍** 🆕 | 🎵 | 音符滚到判定线时按：蓝=A按、橙=B按、紫=两人同时按；自带 BGM 节拍器（♩ 96→150 BPM 随分数加快）；🆕 支持联网双机 | 60s | 错按/漏掉扣机会，8 次失败 |
| **双人架桥** 🆕 | 🌉 | A 移左 / B 移右合力控桥面，接住球再平缓运到右侧出口（运球中突然反向会甩掉球） | 60s | 甩落球 5 次失败 |

**所有玩法零后端**：迷宫固定图、转盘用指令卡（口头报卡号）、剪线口头报色、对暗号用固定密码本、锅炉区间为设备标准 40~60（两端一致）、记忆暗格由 A 端生成 + B 端纯记录、同屏玩法（物资空投/护盾/抬梁/节拍/架桥）用**单设备双人同屏**（共用角色需实时同步，零后端下两台设备无法同步 → 样板阶段一台设备两人各按半边，微信小游戏最终联网后上双机）——同步全走语音。

**玩法类型**：前 6 个 = 「信息不对称 · 一人操作一人指挥」（两台设备）；后 5 个 = 「双人同屏 · 实时合力」（一台设备双控），🧺 物资空投为方向试水作，其余 4 个按用户新方向「AB 都要有操作」落地。

**通用体验规则**（🆕 已应用到全部同屏 + 联网玩法）：
- **开场 3 秒倒计时**：每局开始前屏幕中央 3 → 2 → 1 → GO!，倒计时期间画面冻结（物理不推进），60 秒从 GO 起算，不再"一进就突然开打"。
- **联网惩罚/反馈同步**：房主的实时提示（✔ 命中 / ⭐ +2 / ✘ 漏了 / ✘ 按错了 / 💥 坏物 等）会实时同步显示到加入者屏幕，不再只有房主看得到。
- **联网「再来一局」双方确认**：任一方点「再来一局」→ 对方屏幕弹「♻️ 对方想再来一局 [✔ 同意 / ✘ 拒绝]」→ 双方都同意才开新局（含重新 3 秒倒计时），防止一个人独自强开。

## 结构（以后加新玩法只需加一项）

`PLAYGROUNDS` 数组（id/图标/说明/A端说明/B端说明/单局时长）+ `runModule` 分发 + `renderManual` 按玩法渲染 B 端手册 + 新玩法自己的 run 函数。

**零后端一致性约定**（重要）：A/B 两端无法自动同步随机数，所以每个玩法要么①数据固定（迷宫图、密码本、锅炉区间 40~60），要么②数据由单端持有、另一端靠口头接收（转盘卡号、剪线线序、对暗号符号、记忆暗格密码）。

## 怎么玩

1. **协作玩法（前 6 个）**：两台设备各打开 **同一个链接** → 大厅挑一个玩法 → 各选「当 A · 现场」/「当 B · 后方」→ 开语音协作，**绝对不要看对方屏幕**。
2. **同屏玩法（物资空投 / 护盾 / 抬梁 / 节拍 / 架桥）**：大厅点进去 → 选「一台设备同屏」→ 两人共用一台设备，各按住半边屏（A 左半 / B 右半）。🆕 物资空投另有「联网创建/加入房间」双机形态。
   - **一台设备双人同屏**：两人共用一台设备，各按住半边屏（A 左 / B 右）。
   - **两台设备 · 联网（创建房间）**：房主生成 4 位房间码 → 你控 ← 左移，画面实时同步。
   - **两台设备 · 联网（加入房间）**：输入房主房间码 → 你控 → 右移。**房主做权威主机**跑物理、15Hz 广播状态，加入者渲染同一画面 + 发方向输入（WebRTC/PeerJS 点对点）。

### 联网模式怎么连（重要）

PeerJS 默认公共信令云 `0.peerjs.com` 部署在国外，**国内网络不稳定**（实测时通时断）。推荐本地自建信令：

```bash
cd prototype
npm install peer        # 只需装一次
node start.js           # 同时起：玩法页 http://8080 + 信令 ws://9000
```

然后让**两台手机连「和电脑同一个 WiFi」**，浏览器打开启动脚本打印的地址（含 `?peer=电脑IP&peerPort=9000&peerSecure=0`）。第一台选「创建房间」控 ← 左移，第二台选「加入房间」输码控 → 右移。

异地（不在同一 WiFi）稳定联机：把 `server.js` 部署到一台国内可达的公网服务器，前端用 `?peer=域名&peerPort=443&peerPath=/` 指向它即可（脚本见 `server.js`）。
3. 通关/失败 → 弹「再来一局 / 换玩法」，可打星 + 写一句反馈

## 要验证什么

- **单玩法乐趣**：哪个想玩第二遍？哪个一次就腻？
- **指令卡转盘**：B 查表指挥顺不顺？有没有"对暗号"的感觉？
- **迷宫**：A 还敢自己走吗？B 的安全路线是不是"救命"？
- **剪线**：三次报数+推理紧张吗？
- **对暗号**：抽象符号描述得出来吗？笑点足吗？
- **锅炉**：A 手忙脚乱、B 指挥延迟，8 秒撑不撑得住？
- **记忆暗格**：5 秒传 6 位密码刺不刺激？B 记错互坑好不好笑？
- **物资空投**：两人抢一个角色左右，是"默契"还是"打架"？坏物+阵风够不够狠？
- **双人护盾**：各守半区漏了连坐，是责任分担还是甩锅现场？
- **双人抬梁**：平衡配合有手感吗？一方松手砖滑落，是不是笑点？
- **双人节拍**：紫色同时按，谁没跟上？互坑指数？
- **双人架桥**：运球到门口被队友反向顶回去甩球，笑没笑？
- **难易**：单局时长够不够？失败惩罚狠不狠？

**成功信号**：抢着说话、憋气、爆掉后笑着复盘、主动「再来一局」。
**失败信号**：某玩法烦躁 / 卡住 / 想关掉 = 砍掉或重做。

## 关键参数

- 迷宫：11×15 固定（A/B 同图），最短路径 37 步，A 视野十字 5 格，3 个陷阱（−8s，一次性）
- 转盘：目标指令卡 C1~C10 → `CARD_TABLE` 目标刻度（0-9 各一次），对齐 ±1 格算锁对
- 剪线：6 根随机 · 三步规则（黄/蓝/绿计数，剩余 5→4），10 万次验证必有唯一合法答案
- 对暗号：10 个抽象符号固定库 → 每局随机抽 4 个，B 端全表查
- 锅炉：安全区间固定 40~60（设备标准），A 端起始读数随机 30~70、漂移随机，区间内累计 8s 通关
- 记忆暗格：A 端生成 6 位随机密码，看 5 秒后变问号；B 端记录器纯记录
- 物资空投：**三种形态**（单机同屏 / 联网房主 / 联网加入者）。接货员合力控制（房主或 A 控左 / 加入者或 B 控右）；好物 +1、金箱 +2、坏物 -3s；接够 20 个过关；难度 = 掉落间隔递减 × 坏物比例随进度增加 × 阵风横向吹偏 × **无输入时接货员被"气流"推着左右游走（系统漂移阻力，双方不动也停不下来，需持续对抗）** × 限时 60s × 角色移动惯性阻力（加速 0.7 / 摩擦 0.72）。联网：PeerJS/WebRTC 点对点，房主权威物理 + 15Hz 状态广播，加入者渲染同步画面并发方向输入；房间码 4 位数字。**信令服务器**：默认公共云 0.peerjs.com（国内不稳），推荐 `node start.js` 本地自建（同 WiFi 真机玩）或把 `server.js` 部署到国内公网（异地玩）；前端 `?peer=host&peerPort=port&peerSecure=0` 切换。
- 双人护盾：340×400 canvas 上下分区，A/B 各一护盾片（按住升、松开重力下沉）；两片**无缝+重叠覆盖全宽**（左 8~172 / 右 168~332，中间也接得住）；**按住才挡**（没按的片挡不住）；能量满 20 过关、全队耐久 3 扣完失败
- 双人抬梁：梁两端各 7px 圆点标记 + 中间「收集口」标记；A/B 各抬一端（按住升、松手下沉）；砖落梁即附着、**向低的一侧滚**（梁斜则滚、梁平则停），**滚进梁正中收集口（±18px）即收货**，滚出两端 = 失误；梁自带轻微跷跷板摆动（按住可盖过、不按慢慢晃）；砖满 20 过关、滚出 5 次失败。**核心玩法 = 倾斜梁把砖"送"进中间口，梁平着不动砖停住收不了 → 不操作必然超时失败**
- 双人节拍：音符 340×400 从右向左滚到判定线；蓝 A 按 / 橙 B 按 / 紫 AB 双人同时按（AB 命中 +2）；窗口 ±22px；按对 +1、错按/漏扣 1 次机会（共 8 次）；累计 30 分过关；**自带 BGM 节拍器**：♩ BPM 96→150 随分数加快（每 3 分 +3），每拍 Web Audio 合成 kick（低频咚）+ 每 2 拍 hat（高频嗒），音符每 2 拍生成一个（与拍长同步）。**联网模式**（🆕，同物资空投架构）：房主权威跑音符物理 + 15Hz 广播，房主管蓝音符 + 紫的 A 侧（左半屏/← 键本地按）、加入者管橙音符 + 紫的 B 侧（右半屏/→ 键上报按键 {t:'press',who}），AB 紫色需要两人各自在手机同时按；信令服务器同空投（本地 `node start.js` 或国内公网部署）
- 双人架桥：合力控桥面（同空投手感加速 0.7/摩擦 0.72）；球落桥面接住后**平缓运到右侧出口**送达（出口按桥面右缘 ≥296 判定）；**运球途中突然反向操作会甩掉球**（失误 +1）；送达 5 个过关、甩落 5 次失败；难度 = 接球时机 + 运球不能急转
- 每局随机：指令卡、转盘起始、线序、暗号符号、锅炉起始读数、暗格密码、空投物品流、护盾陨石、抬梁砖、节拍音符、架桥球（迷宫/锅炉区间固定）
- 规则集 `roomlab-v9`，试玩记录存 localStorage（key: `roomlab_records`）

## 技术备注

- 单文件 HTML（HTML+CSS+Canvas+JS），无依赖；URL：无参数=大厅，`?m=maze|dial|wires|code|pressure|vault&role=A|B`=信息不对称玩法，`?m=catch|shield|beam|beat|bridge`=同屏玩法（直达）
- 调试钩子：`_mazeMove` / `_dbgDial` / `_dialApply` / `_dialLock` / `_wirePick` / `_curWires`；同屏玩法各带 `_xxxState/_xxxInject/_xxxMove`（护盾 shield / 抬梁 beam / 节拍 beat / 架桥 bridge / 空投 catch）
- `_genmaze.js`（迷宫生成+BFS+陷阱位验证）、`_genwires.js`（三步剪线 10 万次验证）
- 玩法数据都在 `PLAYGROUNDS` 数组，新增玩法只动这一处 + 对应 run 函数 + B 手册分支
