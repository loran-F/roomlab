# 玩法试炼场 · roomlab-v9（单玩法沙盒）

双人「合作/互坑」解谜的**玩法沙盒**。目标：**把每个玩法独立试玩，验证「单个玩法好不好玩」**；确定哪些好玩，再按密室主题去嵌套组合。

> 🌐 **线上试玩链接**：https://loran-f.github.io/roomlab/ （GitHub Pages，两台设备打开同一链接，各选玩法 + 角色 + 语音协作）

## 为什么拆成单玩法

之前一局 = 迷宫→转盘→剪线 三关串联，测的是"流程节奏"，单玩法好坏被稀释。v7 拆成**玩法大厅**，每个玩法一局独立（各带倒计时 + 通关判定 + 再来一局），可以快速判断"哪个玩法值得留下、哪个砍掉"。

## 玩法大厅（十一个入口，可插拔）

**全部玩法都是「A 现场 + B 后方」两台设备协作模式**（点「当 A」创建房间 / 点「当 B」输码加入，联网实时同步）。信息不对称玩法靠**口头传信息**；实时合力玩法（空投/护盾/抬梁/节拍/架桥）靠**各控一半实时操作**。

**「信息不对称」协作（一人操作一人指挥）：**

| 玩法 | 图标 | A 现场 | B 后方 | 单局 | 失败代价 |
|---|---|---|---|---|---|
| **迷宫走线** | 🗺️ | 盲走探针（视野十字 5 格），听指挥 | 全图：绿安全线 + 红陷阱点，逐句指挥 | 120s | 碰墙 −5s / 踩陷阱 −8s |
| **转盘对接** | 🎛️ | 报目标指令卡号给 B、转针、报针位、喊锁才按 | 指令卡对照表：查卡号得目标刻度，指挥左/右，喊锁 | 90s | 锁错 −3s |
| **剪线排雷** | 🧨 | 报 6 根颜色→剪→再报剩余→剪，共 3 步 | 三步剪线规则树：听报色给答案 | 90s | 剪错任意一步 = 爆炸 |
| **对暗号·接头** | 📖 | 看 4 个抽象符号（复合图形，只能长句描述），输 4 位密码 | 密码本：10 符号 ↔ 数字对照（5 组相似对），听描述认图翻译 | 120s | 输错 −3s |
| **锅炉校准** | 🌡️ | 只看到压力表读数（漂移），按 ⬆⬇ 调、报数 | 握安全区间（40~60），指挥加/减/稳住 | 120s | 撞 0 / 100 = 爆炸 |
| **记忆暗格** | 🧠 | 5 位密码随机逐个闪现（每位 1 秒），边看边口述 | 密码记录器：A 报一位按一位，记满 5 位提交，A 自动判定 | 120s | 传错 −3s 重记 |

**「实时合力」协作（AB 各控一半 · 联网实时同步）：**

| 玩法 | 图标 | A（房主） | B（加入者） | 单局 | 失败代价 |
|---|---|---|---|---|---|
| **物资空投** | 🧺 | 控 ← 左移接货员 | 控 → 右移接货员 | 60s | 接坏物 −3s / 超时未接够失败 |
| **双人护盾** | 🛡️ | 管左半护盾片 | 管右半护盾片 | 60s | 漏陨石全队耐久 −1，扣完失败 |
| **双人抬梁** | 🏗️ | 抬左端 | 抬右端；砖向低的一侧滚，倾斜梁把砖**滚进梁正中收集口**才收下（梁平不动就停住收不了） | 60s | 砖滚出两端 5 次失败 |
| **双人节拍** | 🎵 | 按蓝音符 + 紫的 A 侧 | 按橙音符 + 紫的 B 侧；自带 BGM 节拍器（♩ 96→150 BPM 随分数加快） | 60s | 错按/漏掉扣机会，8 次失败 |
| **双人架桥** | 🌉 | 控 ← 左移桥面 | 控 → 右移桥面；接住球平缓运到右侧出口（突然反向会甩掉球） | 60s | 甩落球 5 次失败 |

**零后端一致性约定**：迷宫多图/锅炉区间固定；转盘卡号、剪线线序、暗号符号、暗格密码由单端持有、另一端靠口头接收（联机时由房主权威生成、随 `enter` 消息同步给加入者）。

**通用体验规则**：
- **开场 3 秒倒计时**：每局开始前 3 → 2 → 1 → GO!，倒计时期间画面冻结，时间从 GO 起算。
- **联网惩罚/反馈同步**：房主的实时提示（✔ 命中 / ⭐ +2 / ✘ 漏了 / ✘ 按错了 / 💥 坏物 等）实时同步显示到加入者屏幕。
- **联网「再来一局」双方确认**：任一方点「再来一局」→ 对方屏幕弹确认 → 双方都同意才开新局（含重新倒计时）。

## 结构（以后加新玩法只需加一项）

`PLAYGROUNDS` 数组（id/图标/说明/A端说明/B端说明/单局时长）+ `runModule` 分发 + `renderManual` 按玩法渲染 B 端手册 + 新玩法自己的 run 函数。

## 怎么玩

两台设备各打开 **同一个链接** → 大厅挑一个玩法 → **A 选「当 A」= 创建房间**（得 4 位房间码）、**B 选「当 B」= 加入房间**（输码进入）→ 开语音协作，**绝对不要看对方屏幕**。信息不对称玩法靠口述传信息；合力玩法 A/B 各控一半实时同步（房主权威物理 + 15Hz 广播）。

### 联网模式怎么连（重要）

PeerJS 默认公共信令云 `0.peerjs.com` 部署在国外，**国内网络不稳定**（实测时通时断）。推荐本地自建信令：

```bash
cd prototype
npm install peer        # 只需装一次
node start.js           # 同时起：玩法页 http://8080 + 信令 ws://9000
```

然后让**两台手机连「和电脑同一个 WiFi」**，浏览器打开 `http://电脑IP:8080/roomlab.html`（无参数时页面会自动识别局域网 IP 连本机信令）。第一台选「当 A 创建房间」，第二台选「当 B 加入房间」输码。

异地（不在同一 WiFi）稳定联机：把 `server.js` 部署到一台国内可达的公网服务器，前端用 `?peer=域名&peerPort=443&peerPath=/` 指向它即可（脚本见 `server.js`）。

## 要验证什么

- **单玩法乐趣**：哪个想玩第二遍？哪个一次就腻？
- **对暗号**：复合相似符号描述得出来吗？"圆里带斜线/圆里带反斜线"这种怎么区分？笑点足吗？
- **记忆暗格**：1 秒闪现 5 位刺不刺激？B 记错互坑好不好笑？
- **物资空投**：两人抢一个角色左右，是"默契"还是"打架"？坏物+阵风够不够狠？
- **双人护盾**：各守半区漏了连坐，是责任分担还是甩锅现场？
- **双人抬梁**：平衡配合有手感吗？一方松手砖滑落，是不是笑点？
- **双人节拍**：紫色同时按，谁没跟上？互坑指数？
- **双人架桥**：运球到门口被队友反向顶回去甩球，笑没笑？
- **难易**：单局时长够不够？失败惩罚狠不狠？

**成功信号**：抢着说话、憋气、爆掉后笑着复盘、主动「再来一局」。
**失败信号**：某玩法烦躁 / 卡住 / 想关掉 = 砍掉或重做。

## 关键参数

- 迷宫：**4 张图随机轮换**（15×11，联机时图号随 `enter` 消息同步；独立分屏 B 端手动切图号），最短路径 29~37 步，A 视野十字 5 格，陷阱全在岔路（−8s，一次性）
- 转盘：目标指令卡 C1~C10 → `CARD_TABLE` 目标刻度（0-9 各一次），对齐 ±1 格算锁对
- 剪线：6 根随机 · 三步规则（黄/蓝/绿计数，剩余 5→4），10 万次验证必有唯一合法答案
- 对暗号：10 个**复合抽象符号**（5 组相似对：圆+斜线、弧+点、山/谷+横线、顺/逆螺旋、三角内/外点）固定库 → 每局随机抽 4 个，B 端全表查
- 锅炉：安全区间固定 40~60（设备标准），A 端起始读数随机 30~70、漂移随机，区间内累计 8s 通关（暂不放进密室事件池，优化后再回归）
- 记忆暗格：A 端生成 **5 位**随机密码，**随机顺序逐个闪现（每位 1 秒）**后全变问号；B 端记录器记满提交、A 自动判定（后期关卡可加位数/提速）
- 物资空投：接货员合力控制（A 控左 / B 控右）；好物 +1、金箱 +2、坏物 -3s；接够 20 个过关；难度 = 掉落间隔递减 × 坏物比例随进度增加 × 阵风横向吹偏 × **无输入时被气流推着左右游走** × 限时 60s × 移动惯性阻力（加速 0.7 / 摩擦 0.72）。联网：房主权威物理 + 15Hz 状态广播，加入者渲染同步画面并发方向输入（PeerJS/WebRTC 点对点）；房间码 4 位数字
- 双人护盾：A/B 各一护盾片（按住升、松开重力下沉）；两片**无缝+重叠覆盖全宽**；**按住才挡**；能量满 20 过关、全队耐久 3 扣完失败
- 双人抬梁：梁两端圆点标记 + 中间「收集口」；A 抬左端 / B 抬右端（按住升、松手下沉）；砖落梁即附着、**向低的一侧滚**，**滚进梁正中收集口（±18px）即收货**，滚出两端 = 失误；梁自带跷跷板摆动；砖满 20 过关、滚出 5 次失败
- 双人节拍：音符从右向左滚到判定线；蓝 A 按 / 橙 B 按 / 紫 AB 双人同时按（+2）；窗口 ±22px；按对 +1、错按/漏扣 1 次机会（共 8 次）；累计 30 分过关；**自带 BGM 节拍器**：♩ BPM 96→150 随分数加快（每 3 分 +3），Web Audio 合成 kick+hat。联网：房主权威物理 + 15Hz 广播，房主管蓝音符+紫 A 侧、加入者管橙音符+紫 B 侧（按键上报 `{t:'press',who}`）
- 双人架桥：合力控桥面（同空投手感）；球落桥面接住后**平缓运到右侧出口**送达；**运球途中突然反向操作会甩掉球**（失误 +1）；送达 5 个过关、甩落 5 次失败
- 每局随机：指令卡、转盘起始、线序、暗号符号、锅炉起始读数、暗格密码+闪现顺序、迷宫图号、空投物品流、护盾陨石、抬梁砖、节拍音符、架桥球
- 规则集 `roomlab-v9`，试玩记录存 localStorage（key: `roomlab_records`）

## 密室爬塔（Roguelike 地图层 · 把玩法串成一条"密室"）

`?m=dungeon` 进入。参考杀戮尖塔，把玩法做成**一条 5 层纵向树状地图**：底部 🚪 起点、顶部 👑 Boss、中间每层 1-3 个事件节点 + 休息点 🏕️（回 1 血）。**必须联网**：密室入口只有「创建房间（我控 A 🔵）」/「加入房间（我控 B 🟠）」两个选项；事件池 10 个 = 5 个实时合力（空投/护盾/抬梁/节拍/架桥）+ 5 个信息不对称（迷宫/转盘/剪线/对暗号/记忆暗格），房主管 A（现场操作）、加入者管 B（后方手册），倒计时/反馈/结算全部实时同步。

- **共用血条** ❤️ 5 格，失败 −1、休息 +1；血扣完 = 整间密室失败退出。
- **前进规则**：两个玩家图标各自沿连线向上走（点节点自动移动，只能沿连线走相邻节点，不能跳分支）；**双方站到同一个未通关节点脚下出现 3 秒进度读条**，读条结束一起进入玩法；读条期间任一玩家走开即打断。
- **决策点**：地图全量连线可见（橙=可走 / 绿=已通 / 灰=未解锁）；进入某节点即锁定同层其余分支，失败会退回上一节点、只能重走当前分支；连通性自检保证每个分支最终都能到 Boss。
- **Boss** 暂为占位符（👑 待设计合作玩法）。
- **联网机制**：房主权威托管地图状态（广播 `{t:'dg'}` 全量 + `{t:'dgcd'}` 读条 + `{t:'enter'}` 进玩法 + `{t:'dgEnd'}` 结算），加入者渲染同一张地图、点自己图标发 `{t:'mvB'}` 让房主移动 B。
- **玩法实时同步**：密室里的玩法全部实时同步——实时合力玩法房主权威物理、15Hz 广播 `{t:'st2'}` 状态，加入者渲染同步画面 + 输入上报 `{t:'in2'}`（B 侧）；空投/节拍复用原链路（`{t:'in'}` / `{t:'press'}`）；信息不对称玩法房主走 A 端界面（3 秒倒计时广播 `{t:'cd'}`）、加入者显示 B 端手册，倒计时 `{t:'dgT'}`、反馈 `{t:'dgMsg'}` 实时同步——**倒计时一致、一方失误双方都有反馈、失败/胜利同时结算**。
- 退出玩法返回地图走 `{t:'dgAbort'}` 双端一致退出；中途有人退出（`{t:'bye'}`）房间关闭回大厅。

## 技术备注

- 单文件 HTML（HTML+CSS+Canvas+JS），无依赖；URL：无参数=主界面，`?m=maze|dial|wires|code|pressure|vault|catch|shield|beam|beat|bridge&role=A`=创建房间（房主 A），`&role=B`=加入房间（B），`?m=dungeon`=密室爬塔（创建/加入两入口）
- 联网：PeerJS/WebRTC 点对点，`peerOpts()` 无参数时按 `location.hostname` 自动判定——局域网 IP/localhost 连本机信令（端口 9000 明文 ws）、公网域名走公共云；`?peer=IP&peerPort=9000&peerSecure=0/1` 显式优先
- 调试钩子：`_mazeMove` / `_dbgDial` / `_dialApply` / `_dialLock` / `_wirePick` / `_curWires` / `MAZES`/`MAZE`/`setMaze`；同屏玩法各带 `_xxxState/_xxxInject/_xxxMove`（护盾 shield / 抬梁 beam / 节拍 beat / 架桥 bridge / 空投 catch）
- `_genmaze.js`（迷宫生成+BFS+陷阱位验证）、`_genwires.js`（三步剪线 10 万次验证）
- 玩法数据都在 `PLAYGROUNDS` 数组，新增玩法只动这一处 + 对应 run 函数 + B 手册分支


## 密室选择界面（2026-09-07）

进入密室后显示 13 张封面，可左右滑动、点击两侧按钮或用键盘方向键切换。名称来自图片文件名，基础信息由 `ROOM_CATALOG` 配置；展示数据暂不改变关卡规则。创建房间为角色 A，加入房间为角色 B，房主所选密室通过 `roomId` 同步给 B。刷新保留选择，返回可继续切换。封面在 `assets/rooms/`，发布时必须同时上传。

本次仅发布选择界面，A–D 玩法改动在后一版本发布。
